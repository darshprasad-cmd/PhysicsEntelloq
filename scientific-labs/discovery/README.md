# Entelloq Discovery

A reactive scientific notebook built with **marimo 0.25.2**. It contains three complete investigations, validated CSV import, model fitting, residual charts, uncertainty estimates, a pendulum parameter sweep, reflection notes, and downloadable JSON/CSV reports.

## Open the browser edition

Serve this folder with any static HTTP server and open `index.html`. The launch buttons open `notebook.html`, a single-file marimo WebAssembly export. All local links are relative so this product can be mounted at `/discovery/` in the Entelloq suite. No Python backend or account is required for the exported notebook.

```sh
python -m http.server 8000 --bind 127.0.0.1
```

The browser downloads versioned marimo frontend assets and the Pyodide Python runtime from public CDNs on first launch. **Internet access is required; this is not a fully offline bundle.** Initialization can take 10–120 seconds or longer on a slow connection. Browser sandbox policies or blocked CDNs can prevent startup; use the native instructions below in that case. Uploaded CSV bytes and calculations stay in the browser in this edition. The frontend assets/runtime are external requests; this is not a zero-network application. Notes and uploaded files are not automatically persisted.

## Run or edit natively

Use Python 3.12 or later and create a project-local virtual environment. This avoids modifying a global Python installation.

```sh
python -m venv .venv
# Windows PowerShell:
.venv/Scripts/Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m marimo run notebook.py --host 127.0.0.1 --port 2718 --no-sandbox
# To edit the actual Python cells:
python -m marimo edit notebook.py --host 127.0.0.1 --port 2718 --no-sandbox
```

The notebook source is `notebook.py`. Scientific functions use marimo's reusable `@app.function` feature and are directly imported by the unit tests. There is no separate JavaScript implementation of the calculations. Charts are accessible labelled SVG generated by Python; table and CSV outputs expose the actual numbers.

Native marimo processes an uploaded file in its Python server. Keep the server bound to `127.0.0.1` for processing on your own device. If you deliberately host that server elsewhere, uploads are transmitted to that server.

## Investigations and input formats

| Investigation | What happens | User CSV headers |
|---|---|---|
| Pendulum | Fit `T=A√L`; infer `g=(2π/A)²`; inspect period residuals and a length sweep. | `length_m,period_s` |
| Projectile | Fit `y=c+bt+at²`; infer `g=-2a`; fit horizontal velocity; inspect vertical residuals. | `time_s,x_m,y_m` |
| Sampling | Sample an analytic cosine and display the continuous signal and indistinguishable folded frequency. | No import; analytic demonstration. |

CSV files must be UTF-8, at most 1 MB and 5,000 rows, with at least four usable measurements. Extra columns are ignored. Missing/non-finite values and duplicate column headers are rejected. Projectile timestamps must be distinct and non-negative. Only use airborne data; a bounce/floor contact invalidates the projectile model. Reality Lab's calibrated CSV columns work directly for projectile fitting.

Synthetic demonstrations are deterministic for a selected integer seed. Pendulum data add zero-mean Gaussian period noise to the ideal small-angle formula. Projectile data add independent Gaussian noise to each position coordinate along an ideal flight up to first ground contact. Sampling uses an analytic cosine and no random noise. The source label remains visible beside every result and is included in the downloaded report. Changing model controls does not alter an imported dataset; controls specifically labelled synthetic affect only generated data.

## Scientific boundaries

- The pendulum assumes small angular displacement, a point bob, fixed length/pivot, uniform gravity and no damping. It uses unweighted least squares through zero in `T` versus `√L`. Large angles, pivot friction, finite bob size and systematic timing errors can bias the result.
- Projectile fitting assumes a constant vertical acceleration and no drag or collisions. The quadratic is solved on a centered and scaled time basis using Gaussian elimination with partial pivoting. A negative inferred `g` means upward curvature in the supplied coordinates; it does not establish negative physical gravity.
- Reported `±1σ` values are **residual-based standard errors**, propagated to gravity. They assume independent equal-variance vertical or period errors and a correct model. They exclude scale, timing, perspective and model errors. They are neither total measurement uncertainty nor guaranteed accuracy bounds. A perfect synthetic fit can yield near-zero residual uncertainty while real systematic uncertainty remains unknown.
- Sampling uses one cosine with zero phase and uniform instantaneous samples. The Nyquist condition is strictly above twice the highest signal frequency with suitable anti-alias filtering. Real camera exposure, noise, finite records and irregular sampling need additional treatment.
- The examples teach inference and its limits. Fits and visual agreement are not experimental validation. All source formulae and residual computations are inspectable.

## Rebuild the browser notebook

The exported file is generated from the editable source; regenerate it after changes. The included builder uses the pinned marimo Python export API and validates that the notebook imports only Python's standard library and marimo. This avoids requiring a native import-analysis helper for a notebook with no local modules. It does not patch marimo.

```sh
python -m marimo check notebook.py
python scripts/export_browser.py
```

The normal upstream alternative is `python -m marimo export html-wasm notebook.py --single-file --mode run --no-show-code --no-sandbox -o notebook.html --force`; it may require `uv` and its Ruff import-analysis helper. That helper was blocked by Windows Application Control on the validation machine, so the self-contained Python builder above was used. The security policy was not modified.

The browser export includes the Python source. Hiding code in the interface does not make it private. `requirements.txt` pins the application dependency; `requirements-lock.txt` records the fully resolved native validation environment. marimo manages its versioned browser runtime dependencies separately.

## Verification

```sh
python -m unittest discover -s tests -v
python -m marimo check notebook.py
python notebook.py
```

`tests/browser.mjs` verifies the static landing page at desktop and mobile widths and the actual WebAssembly notebook. It changes a control and checks recomputation, switches investigations, imports a user CSV, handles an invalid CSV, and downloads the report. Use a Node environment with Playwright installed, start the static server above, then set `DISCOVERY_TEST_URL` and run the script. The default URL is `http://127.0.0.1:8000/`; Chrome is the default channel. `PLAYWRIGHT_MODULE_PATH` may point to an existing installed `@playwright/test` module when testing the suite.

See `VERIFICATION.md` for the recorded run and its limitations.
